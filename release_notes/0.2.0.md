**New in 0.2.0**

- **Any XML runs with `xscape-run` as it is.** Every `../` path of the user XML and the main
  XML is made absolute in copies in the run directory (your file is not changed), and is found
  in the installed X-SCAPE: iSS's tables, `config/HH_LightExcitedMesons.xml`. Before, the
  examples' XMLs (e.g. `examples/pythonic/oo_workflow.xml`) failed in iSS unless a Python run
  had rewritten them.
- **Checks before anything runs** (exit status 3, the reason named; `-f` runs anyway):
  modules the wheel doesn't have (ROOT writers, HepMC, SMASH, FreestreamMilne, CLVisc,
  IPGlasma), XMLs with automatic module setup off (written for C++ test programs; 0.1.0 ran
  nothing and exited 0), Pythia LHAPDF6 sets (0.1.0 crashed), tags X-SCAPE doesn't know (an
  XML newer than the environment), inputs with no file behind them. `JobDir` and the
  production scripts make the same tag and input checks.
- **`runJetscape` in an unprepared directory** stops and points to `xscape-run`. Before,
  3dMCGlauber failed with `sh: ./Metropolis.e: No such file or directory`.
- **pelicanfs and google-crc32c are in the environment:** `osdf://` works out of the box
  (`pythonic/oo_analysis.ipynb` streams from the OSDF with nothing to install).
- **js-contrib's tools are commands:** `xscape-prodwizard` (with the machine `mac_wheel`),
  `xscape-jobmon`, `xscape-check-deposition`, `xscape-h5-inspect`, `xscape-osdf`,
  `xscape-upload-follow` (in this environment, none of their own in `~/.cache`), `xscape-gcs`;
  `xscape-utils DEST` copies `utils/` to read or adapt; `xscape-selftest` checks the
  environment.
- **X-SCAPE with multi_hard:** the event's other hard scatterings (`run_prod_jet.py
  --extra-hard`, minimum bias with `--hard none`), O+O and Ne+Ne at 5.36 TeV
  (`config/OO_5360_jet.xml`, `NeNe_5360_jet.xml`), the bulk observables
  (`analysis/bulk/bulk_obs.py`). Their XMLs need this X-SCAPE: a 0.1.0 environment stops on
  `<extraHard>`.
- **Examples fixed:** `analysis/wake_hadrons.py` runs from a copy of the examples;
  `inspect_bulk_info.py` and `python_bulk_root_writer.py` default to a shipped XML
  (`config/bulk_info_test.xml`).

**Not in the wheel:** ROOT, HepMC, SMASH, FreestreamMilne, CLVisc, IPGlasma, the FNO hydro
(torch), LHAPDF6 for Pythia, Martini's data, X-SCAPE's test hydro files. What needs them now
stops with what is missing named; the README lists which test XMLs and examples run.

The physics of the modules in 0.1.0 is unchanged; files of the two releases should still not
be mixed in one campaign.
