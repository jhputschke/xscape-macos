**New in 1.5**

- **New version numbers.** From this release on, xscape takes the number of the
  [js-contrib](https://github.com/jhputschke/js-contrib) release it is built from: xscape 1.5
  is js-contrib `v1.5`, its `pyjetscape` wheel is pyjetscape 1.5, and the production containers
  of the same release are `jhputschke/xscape-prod:cu126-v1.5` (`cu130-v1.5`, `cu124-v1.5`),
  built from the same X-SCAPE, MUSIC4GPU, iSS and js-contrib commits. 1.5 follows 0.2.0.
- **Parallel showers** (X-SCAPE [#191](https://github.com/JETSCAPE/X-SCAPE/pull/191)):
  `<Eloss><nThreads>` runs the showers of an event on OpenMP threads (N, or -1 for
  `OMP_NUM_THREADS`; 0, the X-SCAPE default, is serial and gives the same events as before).
  The production scripts take `--eloss-threads N`. The events do not depend on the thread
  count, but they differ from serial ones (each shower has its own random streams), so use one
  setting for a whole campaign. **`run_prod_oo_isr.py` now runs the showers in parallel by
  default** (`--eloss-threads -1`): with the same seed, its events differ from 0.2.0's;
  `--eloss-threads 0` gives the serial ones. On an M3 Max a 20-event O+O job takes 46 s
  instead of 52 s at 4 threads; Au+Au jet jobs are dominated by the hydro and do not gain.
- **iSS on threads:** the correlated sampling and the surface preparation run on
  `OMP_NUM_THREADS` threads, with the same hadrons at any thread count (20 O+O surfaces,
  100 oversamples: 10 s to 5 s on an M3 Max).
- **The liquefier's frame** (X-SCAPE [#189](https://github.com/JETSCAPE/X-SCAPE/pull/189)):
  CausalLiquefier solves the deposit's diffusion in the frame of the Bjorken flow at the
  droplet's eta_s (`<frame>bjorken`, the new default). **Behaviour change:** away from
  midrapidity the deposit used to land too close to midrapidity and was partly lost, so jet
  wakes differ from 0.2.0. `<frame>lab` (or `run_prod_jet.py --liquefier-frame lab`) restores
  the old deposit; `fluid` (opt-in) uses the rest frame of the background fluid.
- **A faster jet source** (X-SCAPE [#190](https://github.com/JETSCAPE/X-SCAPE/pull/190)):
  MUSIC's jet source is filled from each droplet's light cone instead of at every cell
  (the same output, 12 to 1.1 ms per fill), and the background's checkpoint sits just before
  the liquefier's `tau_delay`, so jet legs with a droplet from the hard vertex restart from it too.
- **PGun:** `<rapidity>` and `<phi>` of the parton, and `<points>`: several (pT, y) points in
  one run.
- **Tools and examples:** `utils/h5_compare.py` (copy it with `xscape-utils`) compares two HDF5
  files or directories bit by bit; the examples carry `AGENTS.md` / `CLAUDE.md` for AI coding
  assistants.

Tested on an M3 Max (macOS 26): the wheel built from these commits reproduces a checkout build
bit for bit (Au+Au jet production and hadronization), loads no library from outside macOS and
the environment, and passes the smoke suite (every command, test XML, example and notebook).
